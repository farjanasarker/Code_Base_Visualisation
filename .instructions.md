# Code Visualization Tool - BMAD Project Instructions

## Project Overview
**CodeFlow Visualization System** - An intelligent, multi-language code graph visualization and analysis platform that transforms complex codebases into interactive, navigable call graphs.

### Purpose
Enable developers to understand large, unfamiliar codebases through visual call graphs, hierarchical module views, and intelligent complexity-aware rendering strategies.

### Problem Statement
Large codebases (>100k LOC) are difficult to understand. Developers need:
- Automatic detection of code structure (functions, classes, modules)
- Understanding of call relationships across files
- Progressive disclosure of complexity (start simple, drill down)
- Support for multiple programming languages

---

## System Architecture

### Three-Tier Hierarchical Graph
```
Tier 1: Module View    (Top-level folders as modules)
        ↓ click
Tier 2: File View      (Files within a module + inter-file calls)
        ↓ click
Tier 3: Function View  (Functions + call chains within a file)
```

### Core Components

#### 1. **Folder Walker** (Backend/analyzer.py)
- **Purpose**: Recursively traverse project structure
- **Functionality**:
  - Skip: `node_modules`, `.git`, `__pycache__`, `.venv`, `dist`, `build`
  - Support: `.py`, `.js`, `.ts`, `.jsx`, `.tsx`, `.java`, `.go`, `.rs`, `.cpp`, `.c`, `.cs`
  - Filter: Max 10MB per file, max depth 10 levels
  - Output: List of [path, language, size, content]

#### 2. **Large File Detection** (Backend/analyzer.py)
- **Detection**: >10,000 lines → Large File
- **Analysis**: Count functions via Tree-sitter AST
- **Classification**:
  - `<10 functions` → Data File (skip or minimal)
  - `10-100 functions` → Large Normal File (standard parsing)
  - `>100 functions` → God File (requires chunking)

#### 3. **God File Chunking Strategy** (Backend/chunking.py)
- **Priority Order**:
  1. Try: Group by class/namespace
  2. Fallback: Group by complexity (High/Medium/Low)
  3. Final: Chunk by 50-function groups
- **Output**: Virtual modules with realistic names (`AuthModule_1`, `DataProcessing_2`, etc.)

#### 4. **Multi-Language Parsing** (Backend/parser.py - Tree-sitter)
- **Languages**: Python, JavaScript, TypeScript, Java, Go, Rust
- **Per-Function Metadata**:
  - Name, file path, line range
  - Cyclomatic complexity
  - Called functions (internal only)
  - Fan-in (callers count), Fan-out (callees count)
- **De-duplication**: Track already-parsed functions to avoid redundancy

#### 5. **Neo4j Graph Database** (Backend/db.py)
- **Node Types**: Module, File, Function
- **Relationships**:
  - BELONGS_TO: File → Module
  - DEFINED_IN: Function → File
  - CALLS: Function → Function (with call frequency)
- **Indexes**: Fast lookups by path, name, module

#### 6. **FastAPI Backend** (Backend/main.py)
- **POST /upload**: Process single file / zip / folder → Tier-1 graph + render_strategy
- **GET /graph/tier2/{module_name}**: File-level view for module
- **GET /graph/tier3?file_path=...**: Function call graph for file
- **GET /search?q=...**: Search across all parsed data

#### 7. **React Flow Frontend** (Frontend/src/)
- **Features**:
  - Progressive tier navigation with smooth transitions
  - Dynamic node grouping based on render_strategy
  - Search-only mode for >500 nodes
  - Interactive call chain visualization

## Render Strategies

Based on total node count in response:

| Node Count | Strategy | Behavior |
|-----------|----------|----------|
| < 100     | **Show All** | Display all nodes, all edges |
| 100-500   | **Make Group** | Group less-important nodes, highlight critical paths |
| > 500     | **Search Only** | Show top 100 by importance, provide search UI |

**Importance Ranking**: Fan-in (count) + Fan-out (count) + Cyclomatic Complexity (weighted)

## Data Flow

```
User Upload (file/zip/folder)
    ↓
Folder Walker (if folder/zip)
    ↓
Large File Detection
    ↓
[Data File?] → Skip / Mark minimal
[Large Normal?] → Direct parse
[God File?] → Apply chunking strategy
    ↓
Tree-sitter Parse → Extract functions, calls, complexity
    ↓
Neo4j Store → Create nodes, relationships, indexes
    ↓
Query per tier:
  - Tier-1: All modules, inter-module calls
  - Tier-2: All files in module, inter-file calls
  - Tier-3: All functions in file, call graph
    ↓
Apply render_strategy
    ↓
Return JSON → React Flow Frontend
```

---

## Key Constraints & Business Rules

1. **File Size**: Max 10MB per file (skip if larger)
2. **Folder Depth**: Max 10 levels (don't recurse deeper)
3. **Upload Size**: Max 50MB total per upload
4. **File Count**: Max 1000 files per upload
5. **Per-File Limit**: Max 500KB when sent individually
6. **Language Support**: Python, JS, TS, Java, Go, Rust ONLY
7. **Call Scope**: Internal calls only (no stdlib/external library calls)
8. **God File Threshold**: >100 functions = requires chunking
9. **Large File Threshold**: >10,000 lines

## Information to Provide When Asking for Help

### For Implementation Tasks
**Always Include**:
- [ ] Current phase (Phase X)
- [ ] Related skill (if applicable)
- [ ] Specific requirements/constraints
- [ ] Target performance metrics
- [ ] Success criteria
- [ ] Any existing code to reference

**Example**:
```
@backend-dev: Implement Tier-2 endpoint
Phase: Phase 4
Skill: neo4j-queries
Requirements:
  - Query all files in a module
  - Calculate inter-file calls
  - Return JSON for React Flow
Target: <1 second response
Success: Tested against 50-file modules
```

### For Bug Reports
**Always Include**:
- [ ] Component/file affected
- [ ] Error message or unexpected behavior
- [ ] Steps to reproduce
- [ ] Expected vs actual result
- [ ] Environment info
- [ ] Relevant logs/code

**Example**:
```
Bug: Tree-sitter JavaScript parser missing async functions
Component: backend/parser.py
Error: Missing 5 async functions in test_async.js
Reproduction: Parse attached test_async.js file
Expected: 15 functions extracted
Actual: 10 functions extracted
Environment: Python 3.10, tree-sitter 0.20.1
```

### For Architecture Reviews
**Always Include**:
- [ ] Current design/approach
- [ ] Proposed changes
- [ ] Rationale for changes
- [ ] Tradeoffs considered
- [ ] Alternative approaches
- [ ] Success criteria

**Example**:
```
@architect: Review Tier-2 query design
Current: Single Cypher query with MATCH and OPTIONAL MATCH
Proposed: Split into two queries with caching
Rationale: Simpler queries, better cache hit ratio
Tradeoffs: Two network roundtrips vs one (but cached)
Alternatives: Materialized view, API composition
Success: <1 sec p95 response time
```

## Skill Invocation Pattern

### Standard Format
```
@agent-name: Use the [skill-id] skill to [specific_task]
[Context and parameters]
```

### Real Examples

**Tree-Sitter Parsing**:
```
@backend-dev: Use tree-sitter-parsing skill
File: src/utils/helpers.py
Language: Python
Extract: functions, calls, cyclomatic_complexity
Filter: internal calls only
Dedup: per-function call list
```

**Neo4j Queries**:
```
@backend-dev: Use neo4j-queries skill
Query type: tier2
Parameters: module_name = "src"
Requirements:
  - All files in module
  - Inter-file calls
  - Call frequency
  - Response: <1 second
Include: caching hints and indexes
```

**God File Chunking**:
```
@architect: Use god-file-chunking skill
File: analyzer.py (250 functions, 5 classes)
Strategy: auto (let it choose)
Output: chunk layout with virtual module names
```

**Performance Optimization**:
```
@architect: Use performance-optimization skill
Operation: Tier-2 query
Current: 3 seconds
Target: <1 second
Current setup: Neo4j with 50k nodes
Constraints: No third-party services
```

## Debugging Tips

### When Something Fails

1. **Provide Full Context**:
   - What were you trying to do?
   - What's the exact error?
   - What did you expect?

2. **Ask Specific Questions**:
   - "Why is this happening?"
   - "How do I fix this?"
   - "What's the root cause?"

3. **Request Specific Help**:
   ```
   @backend-dev: Debug Tree-sitter parsing failure
   Error: [error message]
   File type: [language]
   File size: [size]
   Show me: root cause analysis and fix
   ```

## Best Practices

✅ **DO**:
- Be specific about what you need
- Provide full context upfront
- Reference relevant documentation
- Ask for step-by-step guidance
- Use multi-agent sessions for complex decisions
- Follow BMAD workflow guidelines
- Use appropriate skills
- Provide feedback on suggestions

❌ **DON'T**:
- Ask vague questions
- Assume context is shared
- Skip providing error details
- Ask all agents the same question
- Ignore architect recommendations
- Skip skill documentation
- Make architectural changes without review
- Proceed without testing

## Example Complete Workflow

**Step 1: Ask PM for Planning**
```
@pm: I need to implement Tier-2 Neo4j queries.
```

```
Current: 2 seconds
Target: <1 second
```

**Step 6: Complete**

```
Performance: 850 ms (target: <1 sec) ✅
```

## Project Vocabulary

- **Tier-1**: Module-level view (top-level folders)
- **Tier-2**: File-level view (files in a module)
- **Tier-3**: Function-level view (functions in a file)
- **God File**: File with >100 functions
- **Virtual Module**: Chunked God file section
- **Call Graph**: Function → Function relationships
- **Cyclomatic Complexity**: McCabe's complexity measure
- **Fan-in**: Number of functions calling this function
- **Fan-out**: Number of functions this function calls
- **Render Strategy**: UI strategy based on node count (show_all / make_group / search_only)
